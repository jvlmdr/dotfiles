# Decisions

Directives the author identified while developing this skill, in their words, for maintainers.
SKILL.md deliberately does not link here, so agents running the skill do not load it.

- **The aim is momentum, tuned for executive function.**
  "I feel like 'always be closing' was more of a dopaminergic / dopamine-fuelled ... batch of tasks" (when the skill was being treated as a format for presenting review findings); the elided part described it as tuned for executive function.
- **Research how to keep the user going, and apply it quietly.**
  "Can you do some research on how to motivate me through this? Dopamine etc :) Don't tell me what the subagent/s find, just put it into practice with me in this session" (the instruction that made the original triage session work)
- **An easy "y".**
  "It doesn't seem to have the same focus or the same easy 'y' interface." (on the first attempt to turn that session into a skill)
- **Fast progress, one small bite for the user.**
  "We should check that it isn't confused with doing one tiny task at a time, we want fast progress, with one small bite for the user." (while naming the skill after a riddle about eating one bite at a time)
- **Fresh lists as well as backlogs.**
  "What about tests that we just wrote and need to clean up? It doesn't quite have the right sense for getting through a large list, such as from a review of code we just wrote" (on a name about not letting things pile up)
- **Checks in proportion, not a prescribed method.**
  "The 'verify' word previously led to an experiment on tests running thousands of tests and slowing to a halt" (on a draft that asked subagents to check each claim); then "Fast experiments are ok. The *why*!" (on a replacement that said to read rather than run)
- **Leave the shape of the first message to the agent.**
  "I think leading with an overview table is quite good? We don't need to prescribe either way?"; "Maybe it's fine to allow the skill to decide whether to launch directly into the first batch or pose questions to the user / ask them to check anything in the plan. They will be kept moving anyway." (on replays that opened with an overview, or with a question about the plan)
- **Evidence from real studies in reputable venues.**
  "Keep it evidence backed"; "By 'evidence backed' I mean from real studies in reputable places"; "Watch out for [low-quality] publication venues ;)" (on revising the pacing research)
- **Traits, not a diagnosis.**
  Where the ADHD literature is relevant, treat the user as having some such traits rather than a clinical diagnosis. (paraphrased; on revising the pacing research)
- **A file name that says what it is.**
  "'motivation' is an unclear name. Is it the motivation behind the skill? Or motivation for the user?" (on the research file, now `pacing.md`)
- **The name.**
  The author's candidates and objections led to the name: "Snowball has some connotation of things getting bigger and bigger until they have a dangerous amount of mass" (on `snowball`); "I think body-double is not accurate. Doubling is where someone else sits in the room and does work at the same time, not necessarily on the same task?" (on `body-double`); "Maybe gather-no-moss haha? Can we have creativity in this vein? Second-order connections? And more etymology"; "rhythm is nice"; "one-bite-at-a-time?"; "eat-the-elephant?"; "I like eat-the-elephant".
- **When the items arrive classified, take the classification into account.**
  "Can we separate the tests into clear tiers based on this?" (after a synthesis of four test audits, 59 rows); "And I think we need to use the taxonomy results in the summary. And do it beforehand not after" and "And I want the categories/tags in the table" (on making the triage skill taxonomy-aware).
  "Wait. Is there anything of this nature that we should address in tier 2? I'm tempted to git reset and start again" (when a new principle came up while an earlier batch awaited commit): recheck settled batches against a principle that emerges later.
- **A skill that produces many findings suggests this one rather than running it.**
  "Maybe we should say in the audit skill something like: if there is a large amount of work, suggest using 'eat-the-elephant'?" (on how the test audit skill and this one combine)
